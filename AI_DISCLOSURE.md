## 3. Attribution of PromQL and regex

As the assignment requires, every complex AI-generated PromQL expression or regex is commented in the configuration file with the prompt used:

- **`rules/recording_rules.yml`**: a header quoting the session prompt, then a `# AI prompt: "..."` line above each rule. Regexes such as `fstype!~"tmpfs|ramfs|overlay|squashfs|nsfs|fuse.*"` also get an `# AI regex:` line.
- **`grafana/dashboards/caption-app.json`**: every non-trivial query starts with a `# AI prompt: "..."` line. PromQL treats `#` as a comment, so the query still runs. You can see these in each panel's query editor. The dashboard description repeats the session prompt.

## 4. Manual calculation of the metric logic

The assignment allows AI-generated PromQL but requires each metric's logic to be calculated by hand. The calculations are in [`A4_Report.pdf`](A4_Report.pdf). They were produced like this:

- **Raw values:** captured during the recorded run of my stack (25 October 2026, 22:54), as `/metrics` snapshots of the app (`:18000`) and node_exporter (`:9100`) plus raw Prometheus samples. No PromQL functions were used for the hand side.
- **Arithmetic:** each metric's formula was applied with plain arithmetic. As listed in section 1, the AI assistant did the capture and arithmetic at my request.
- **Comparison:** each result was compared with Prometheus and the Grafana panel at the same moment.

Every step is written out in the report so I can re-derive each number by hand during evaluation.

| # | Metric (type) | Formula | Raw values used | Hand result | Prometheus / dashboard | Match |
| --- | --- | --- | --- | --- | --- | --- |
| M1 | `caption_images_processed_total{mode="bulk",status="success"}` (Counter → rate) | (v_last − v_first) ÷ (t_last − t_first) | 73 at 22:54:23.760, 83 at 22:54:38.760 | 10 ÷ 15.000 = **0.6667 img/s** | `rate(...[20s])` 0.6667; Throughput panel 0.6667 | ✔ |
| M2 | `caption_images_processed_total{status}` (Counter → ratio) | failed ÷ (failed + success) | lifetime 3 failed of 98; this run 1 of 25 | **3.061 %** lifetime, **4.000 %** this run | Prometheus 3.061 %; *Image error ratio* tile 4.000 % | ✔ |
| M3 | `caption_request_seconds` (Summary) | `_sum` ÷ `_count` | lifetime 121.144 s ÷ 3; this job 33.823 s ÷ 1 | **40.381 s** lifetime, **33.823 s** this job | Prometheus 40.381 s; app UI "Total time" 33.8 s | ✔ |
| M4 | `caption_inference_seconds_bucket{mode="bulk"}` (Histogram) | p95 = lower + (upper − lower) × (rank − c_lower) ÷ (c_upper − c_lower) | N = 92, rank = 87.40, buckets le=1.5 → 75, le=2 → 91 | 1.5 + 0.5 × 12.40 ÷ 16 = **1.8875 s** | `histogram_quantile(0.95, …)` 1.8875 s | ✔ |
| M5 | `node_cpu_seconds_total{mode="idle"}` (node Counter) | 1 − Δidle ÷ (Δt × n_cpu) | Σidle 145742.13 → 145810.16 over 9.988 s, 22 CPUs | 1 − 68.03 ÷ 219.74 = **69.0 %** | same 10 s window 69.2 % (panel's 30 s window: 62.1 %) | ✔ |
| M6 | `process_cpu_seconds_total` (app Counter) | Δcpu ÷ (Δt × n_cpu) | 972.07 → 1056.75 over 9.988 s | 84.68 ÷ 219.74 = **38.5 %** | same 10 s window 37.5 % (panel's 30 s window: 32.4 %) | ✔ |
| M7 | `node_memory_MemAvailable_bytes`, `node_memory_MemTotal_bytes` (Gauges) | 1 − MemAvailable ÷ MemTotal | 5,057,167,360 ÷ 15,653,351,424 | **67.69 %** | Memory panel 67.31 % | ✔ |
| M8 | `node_filesystem_avail_bytes`, `node_filesystem_size_bytes` on `/` (Gauges) | avail ÷ size | 28,482,977,792 ÷ 58,735,820,800 | **48.49 %** | Disk free space panel 48.49 % | ✔ |

Notes on the comparisons:

- **Exact matches (M2–M4):** lifetime counters, the Summary and the Histogram match exactly, because both sides read the same scraped values.
- **M1:** matches exactly, because the counter rose at a steady rate over the 20 s window.
- **M5 and M6:** match Prometheus to within 1 percentage point when it uses the same 10 s window. The dashboard panels average over 30 s, which during the ramp-up still included the seconds before the bulk job started, so they read a few points lower.
- **M7:** memory is a gauge that moves between scrapes, so the panel (taken from the nearest scrape) differs by 0.4 percentage points.
